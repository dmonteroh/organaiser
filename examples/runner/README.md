# Runner-mode examples

What [runner mode](../../workflows/dev-workflow.md) actually produces on disk: a committed, deterministic fake-adapter board run in the production `.orga/runs/<runId>/` shape, plus one sanitized real vendor stream.

## Board run

[board-run/](board-run/) is a fake-adapter run of `dev-workflow` against two dependency-ordered tasks (`task-dependent` depends on `task-blocker`), driven to a terminal `integrated` disposition for both, one attempt each. Its tree is the real production shape: `board-run/.orga/runs/<runId>/BOARD.md`, `events.jsonl`, and per task `tasks/<taskId>/{ledger.json, attempt1-artifacts/}`.

All of it is deterministic fake output: no real model or vendor process ran. `implement`, `review-spec`, `review-quality`, and `cross-task-review` each replayed a staged pass result from the `FakeAdapter`, exactly as `runner`'s own fixtures do. The write boundaries themselves are real: `BOARD.md` is `renderBoard`'s real markdown, `events.jsonl` is the real run event log, `ledger.json` is real `writeLedger` output, and each `attempt1-artifacts/` directory holds the three files a real all-pass development round writes (`dispatch-log.tsv`, `spec-reviewer.report.txt`, `quality-reviewer.report.txt`).

Excluded on purpose: `state.sqlite`, `config.resolved.json`, `supervisor.log`, `supervisor.pid`, and any `test-supervisor-*.log` are real production output of the run, but they are binary, machine-local, or log noise rather than the artifact shape this example documents.

## Live capture

[live-capture/normal-success.jsonl](live-capture/normal-success.jsonl) is a real recorded vendor stream, copied byte for byte from `runner/evals/captures/claude/2.1.245/normal-success.jsonl`. Unlike the board run, this is genuine Claude Code output, not fake-adapter output. It was redacted (`sanitizeCaptureLine`, `runner/src/adapters/captures.ts`) before it ever reached the repository; the copy here carries the same redaction, and re-running the sanitizer over it changes nothing.

## Regenerating the board run

`board-run/` is produced by a committed maintenance script, not by a production CLI invocation:

```
node runner/scripts/regenerate-runner-example.ts
```

Run it from the repository root. Every filesystem write it hands to the runner (project directory, store, workspace, streams directory, supervisor log) lives under a scratch directory outside this checkout; the only writes into this repository are the final copies into `board-run/`. Because each run generates a fresh `runId`, regenerating replaces the previous `.orga/runs/` contents rather than adding to them. The live capture is not regenerated by this script; it is copied once from its source and never hand-edited.
